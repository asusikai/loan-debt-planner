# 개선 로그 (Task 11~15)

## 개요

- 고도화 범위: 중도상환수수료 반영, 정렬 로직 개선, 금액 정밀도 강화, 테스트 확장, 훅 의존성 정비
- 목표: 계산 결과 신뢰도와 유지보수성 향상, 회귀 위험 감소

## 변경 전후 비교

### Task 11 - 중도상환수수료 반영

- 변경 전: 수수료 지표 부재, 순 절감액 비교 어려움
- 변경 후: `totalFeesPaid`, `netSavings`를 통해 비용 효과를 함께 판단 가능

| 구분 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 전략 비교 기준 | 총이자 중심 | 총이자 + 수수료 + 순절감액 |
| 의사결정 포인트 | 이자 최소화 단일 지표 | 실질 절감액 기준 선택 가능 |
| 리포트 해석성 | 비용 요소 분리 어려움 | 비용 구성요소 분리 확인 가능 |

### Task 12 - 정렬 로직 고도화

- 변경 전: 전략별 단순 정렬 중심
- 변경 후: `SortProvider` 기반 분리로 정렬 책임 명확화, 0% 금리/만기 보조 기준 반영

| 구분 | 기존 | 고도화 후 |
| --- | --- | --- |
| 핵심 정렬 기준 | 단일 기준 중심 | 주 기준 + 보조 기준(tie-breaker) |
| 구조 | 전략 함수 내부 결합 | `SortProvider`로 책임 분리 |
| 테스트 범위 | 기본 시나리오 중심 | 0% 금리/만기 임박/엣지 케이스 포함 |

## 트러블슈팅

### Task 13 - 금액 정밀도

- 문제: 장기 시나리오에서 누적 오차 검증 어려움
- 대응: `currency` 유틸 도입으로 금액 연산 규칙 통일
- 구현 포인트: 반올림/합산/차감 규칙을 단일 유틸로 통합해 엔진 산술 경로 일관화

### Task 15 - 훅 의존성 관리

- 문제: 핸들러 참조 변경으로 인한 재실행 가능성
- 대응: `useCallback` 및 기능형 상태 업데이트 적용으로 참조 안정성 강화
- 구현 포인트: 삭제 확인 흐름에서 기능형 업데이트를 적용해 의존성 축소 및 stale 참조 위험 완화

## 우선순위 조정 배경

- 엔진 계산 정확성 확보가 선행되어야 UI/문서 지표 신뢰 가능
- 따라서 기능 추가보다 검증 확장(Task 14)과 구조 정리(Task 12, 15)를 우선 적용
- 의사결정 흐름
  - 1순위: 계산 정합성(수수료/정밀도/종료 조건)
  - 2순위: 정렬 책임 분리와 테스트 가능 구조 확립
  - 3순위: 화면/문서 반영을 통한 사용자 해석성 강화

## 기술적 통찰

- 계산 도메인은 금액 연산 규칙을 먼저 고정해야 회귀 테스트 해석 가능
- 전략 정렬 책임 분리는 테스트 단위 분리에 직접적인 이점 제공
- 훅 의존성 정리는 린트 대응을 넘어 런타임 안정성 확보 수단
